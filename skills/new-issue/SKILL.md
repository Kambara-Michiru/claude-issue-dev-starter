# Claude への依頼書（Issue）を一緒に作る

相手は開発の専門家ではありません。質問は1回に1つ、選択肢を出して答えやすくしてください。

## 1. 聞き取る

引数があれば、それを「やってほしいこと」の最初の案として使う。次の順に聞く。

1. **やってほしいこと**：何をどう変えたいか
2. **なぜ**：誰のため、何に困っているか（1文でよい）
3. **完成の条件**：「これができていたら OK」を2〜4個。相手が思いつかなければ、あなたが案を出して選んでもらう。どれも「見ればわかる」形にする（例：「スマホで見ても文字が切れない」）
4. **やらないこと**：今回は変えてほしくないところ

聞きながら、必要ならリポジトリの中を見て、関係しそうなファイル名を「参考になるもの」に入れる。

## 2. 大きさを確かめる

1つの依頼書は「1つの PR で終わる大きさ」にする。次のどれかに当てはまったら、分けることを提案する。

- 「〜と〜と〜をしてほしい」のように、やりたいことが3つ以上ある
- 完成の条件が5個を超える
- 「サイト全体を」「全部」のように範囲が広い

分ける場合は、親の Issue を1つ作り、それぞれの依頼書の本文に「親：#番号」と書く。

## 3. 見せて、OK をもらう

次の形で本文を組み立て、相手に見せる。

```markdown
### やってほしいこと
…

### なぜやりたいか（背景）
…

### 完成の条件
- [ ] …
- [ ] …

### 参考になるもの
…

### やらないでほしいこと
…
```

タイトルは「[依頼] 」で始め、20文字くらいで中身がわかるようにする。

## 4. 作る

OK をもらったら、本文を一時ファイルに書いて Issue を作る。

```bash
gh issue create --title "[依頼] …" --body-file <一時ファイル>
```

作ったあと、相手に聞く：「このまま Claude に作業を始めてもらいますか？」選択肢を出す。

- **作って、マージは自分でする** → `gh issue edit <番号> --add-label claude`
- **作って、条件を満たせば自動でマージしてよい** → `gh issue edit <番号> --add-label claude-auto`
  - 見た目や文章の小さな変更に向いている。ログイン、お金、個人情報、大きな変更は `claude` をすすめる
  - 自動マージが練習モードのうちは、判定がコメントされるだけで、マージは人がすることも伝える
- **まだ** → 「あとで GitHub の画面で Labels から claude か claude-auto を付ければ始まります」と伝える

ラベルを付けたら、数分〜十数分で依頼書に報告が届くこと、`gh issue view <番号> --web` でブラウザから見られることを伝える。

一時ファイルは最後に消す。
