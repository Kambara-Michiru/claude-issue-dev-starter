# 3. 依頼書（Issue）の書き方

Claude の作業の出来は、依頼書の書き方で大きく変わります。**新人のアシスタントに初めて仕事を頼むつもり**で書いてください。

> `/issue-dev:new-issue` を使えば、Claude が質問しながら依頼書を整えてくれます。

## 依頼書の5つの欄

| 欄 | 書くこと | なぜ必要？ |
|---|---|---|
| やってほしいこと | 何をどう変えたいか | これがないと始まらない |
| なぜやりたいか | 目的や困りごと | 細かいところを正しく判断できる |
| 完成の条件 | 「これができたら OK」のチェックリスト | 終わりがはっきりする。あなたの確認にも使える |
| 参考になるもの | 関係するファイル、似た例、画像 | 探す手間が減り、イメージが合う |
| やらないでほしいこと | 今回は触らないところ | 頼んでいない変更を防ぐ |

## 良い例と、よくない例

### よくない例

> トップページをいい感じにして

- 「いい感じ」が人によって違う
- どこまでやれば終わりかわからない
- 全体を変えてしまうかもしれない

### 良い例

> **やってほしいこと**
> トップページの見出しの下に、自己紹介の文章を3行で入れてほしい
>
> **なぜやりたいか**
> 初めて来た人に、どんな活動をしているか伝わっていないため
>
> **完成の条件**
> - [ ] 見出しのすぐ下に、3行くらいの自己紹介がある
> - [ ] 「デザインの勉強をしている学生です」という内容が入っている
> - [ ] スマホで見ても文字が画面からはみ出さない
>
> **やらないでほしいこと**
> 色やフォントは変えないでください

## うまくいくコツ

1. **1つの依頼書には1つのことだけ。** 「ついでにあれも」と思ったら、別の依頼書にします
2. **完成の条件は「見ればわかる」形で。** 「きれいに」ではなく「スマホで文字が切れない」
3. **大きなことは分ける。** 「サイトを作り直す」は、「トップページの見出し」「プロフィール欄」「お問い合わせ」のように小分けにします
4. **わからないことは、わからないと書く。** 「どのファイルかわかりません」で大丈夫。Claude が探します
5. **画像を貼ってもいい。** 「こんな感じにしたい」というスクリーンショットは強い手がかりです

## Claude から質問が来たら

依頼があいまいなとき、Claude は作業せずに Issue へ質問を書くよう CLAUDE.md で決めてあります。
質問に答えたら、コメントで `@claude 答えました。作業を進めてください` と書くと再開します。
