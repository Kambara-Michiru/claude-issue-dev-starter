# 5. 安全と費用

## お金の話

この仕組みでは、2種類の費用がかかります。

| 何に | どのくらい | 減らすには |
|---|---|---|
| **Claude の利用** | 1つの依頼で、作業役（チェックが落ちたらもう1回）とレビュー役の 2〜3 回動きます。有料プランのトークンを使うなら、プランの利用上限の範囲内。API キーなら使った分だけ。ほかに週1回の点検 | 依頼書を具体的に書く、1つの依頼を小さくする |
| **GitHub Actions の実行時間** | 公開リポジトリは無料。非公開リポジトリは、プランごとの無料枠を超えた分が有料 | 必要なときだけ動かす |

このスキル集のワークフローには、使いすぎを防ぐしかけが入っています。

- **時間の上限**：作業は45分、レビューは20分で自動的に止まります（`timeout-minutes`）
- **やりとりの上限**：Claude が試行錯誤する回数に上限があります（`--max-turns`）
- **二重に動かない**：同じ依頼書で同時に2回動かないようにしています（`concurrency`）

> 最新の料金は [Claude の料金](https://claude.com/pricing) と [GitHub Actions の料金](https://docs.github.com/en/billing/concepts/product-billing/github-actions) で確認してください。

## 安全の話

### 本番（main）が変わるのは、2つの場合だけ

1. **あなたがマージしたとき**（`claude` ラベルの依頼、または関門が ❌ を出したもの）
2. **関門が自動マージしたとき**（`claude-auto` ラベル、かつ本番モード、かつ条件をすべて満たしたもの）

Claude（作業役もレビュー役も）は、main に直接書き込みません。コミット、PR 作成、マージは決まった手順（ワークフロー）がやり、マージしてよいかは関門が決まったルールで判定します。

### 自動マージの安全装置

| 安全装置 | 何を防ぐか |
|---|---|
| 最初は練習モード（shadow） | 判定が信頼できるとわかるまで、実際にはマージしない |
| `claude-auto` を付けた依頼だけが対象 | 人が「任せてよい」と決めたものだけ |
| メンバーが書いた依頼書だけ | 知らない人の依頼書は自動で通さない |
| 作業役とは別のレビュー役 | 作った本人の甘い自己採点 |
| 危険度が「低」のものだけ | ログイン、お金、個人情報、仕組みの変更など |
| 10 ファイル・300 行まで | 失敗したときの影響が大きくなること |
| 守るべきファイルに触れたら対象外 | 仕組みそのものや鍵を、自動で変えてしまうこと |
| 関門は main の版で動く | PR の中から関門をゆるめること |
| チェック後に中身が変わったらマージしない | 古い確認で新しい変更を通すこと |
| 判定できないときはマージしない | エラーや想定外のときは、必ず人に回す |

それでも、AI のレビューは確率で動くので、まちがえることがあります。**ログイン、お金、個人情報、データの削除にかかわる依頼には、`claude-auto` を使わないでください。**

### 止め方

- 1つの PR だけ：`hold` ラベルを付ける
- 全部：`/issue-dev:automerge off`（または Actions タブで「Claude（自動マージの関門）」を Disable workflow）
- 元に戻す：マージされた PR の画面の **Revert** ボタン

### main を守る設定

公開リポジトリ、または GitHub の有料プランなら、`/issue-dev:setup` のステップ 7 で「main は PR からしか変えられない」「機械のチェックが通らないとマージできない」設定（ルールセット）を入れられます。無料プランの非公開リポジトリでは使えませんが、関門は同じように働きます。

### 誰が Claude を動かせるか

- Claude を動かせるのは、**そのリポジトリに書き込み権限のある人だけ** です。知らない人が公開リポジトリで `@claude` と書いても動きません
- `claude` ラベルを付けられるのも、権限のある人だけです
- ほかのボットが Claude を呼ぶことも、初期設定ではできません

### 鍵（トークン・API キー）の扱い

- 鍵は **GitHub の secret（金庫）にだけ** しまいます。ファイルに書いたり、チャットに貼ったりしないでください
- うっかり人に見せてしまったら、すぐに作り直します
  - サブスクリプションのトークン：`claude setup-token` で作り直し、`gh secret set CLAUDE_CODE_OAUTH_TOKEN` で入れ替える
  - API キー：https://platform.claude.com でキーを削除して新しく作る

### 公開リポジトリにするときの注意

公開リポジトリは、世界中の誰でも中身を読めます。次のものは入れないでください。

- パスワード、API キー
- 住所や電話番号などの個人情報
- 公開してはいけない仕事の資料

### Claude GitHub App の権限

Claude の GitHub App をインストールすると、ファイルの読み書き、Issue や PR へのコメントなどの権限を渡します。必要なリポジトリにだけインストールするのがおすすめです（インストール時に「Only select repositories」を選ぶ）。

### 仕組みをやめたいとき

1. `.github/workflows/` の `claude.yml`、`claude-work.yml`、`claude-verify.yml`、`claude-gate.yml`、`claude-gardener.yml` を削除する（`.github/harness/` と `scripts/check.sh` は残しても害はありません）
2. リポジトリの Settings → Secrets and variables → Actions で、鍵を削除する
3. 必要なら、GitHub の Settings → Applications から Claude の App をアンインストールする

次は [困ったとき](06-troubleshooting.md) へ。
